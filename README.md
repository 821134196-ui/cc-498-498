# 花语 · 婚礼花艺执行台

花艺团队按婚礼区域拆分花材清单：记录品种、颜色、枝数、到货日、冷藏位置与效果图；
采购到货先验收，布置人员按区域领料并上传完工照片。缺货替代、版本确认、现场异常、
撤场回收、多组重复领料全部留痕。

- **零依赖**：仅使用 Python 3 标准库（`sqlite3` + `http.server`）+ 原生 JS，无需 pip / npm。
- 数据存 **SQLite**（数量与版本），照片存 **本地** `data/uploads/`，确认通知用**模拟适配器**（落库不外发）。

## 一条命令启动

```bash
./run.sh                 # 重建样例数据（含缺货替代、临时追加）并启动，默认 8000 端口
PORT=8012 ./run.sh       # 指定端口
```

打开 http://127.0.0.1:8000

> `./run.sh` 每次会重建样例库；只想补数据可用 `python3 -m app.seed --keep`，
> 只想起服务用 `python3 -m app.server`。

## 六个页面

| 页面 | 能力 |
|---|---|
| 花材配额 | 区域**平面图**点击联动花材清单；版本新建/客户确认；全局库存占用表（入库/已领/可用） |
| 到货质检 | 登记到货（花材、枝数、到货日、冷藏位）→ 验收：合格/萎蔫/提前开花/运输折损 + 可用枝数 + 质检照 |
| 区域领料 | 按已确认版本配额领料；支持「已确认替换」「临时追加单」；多组重复领料自动预警留痕 |
| 替换确认 | 替代花材 + **价差** + 视觉差异提案；**替换前后照片并排并标出枝数与价差**；确认/驳回 |
| 现场核对 | 区域核对、完工照片上传、异常（萎蔫/开花/折损/追加/回收）记录、撤场回收登记 |
| 结算 | 分区汇总：清单金额 + 已确认替换价差 + 现场追加，附领料/回收/质检损耗 |

## 核心业务规则（`app/service.py`）

1. **同一枝数不能被两个区域重复占用**：花材库存全局共享，
   `可用 = Σ质检入库 usable_stems − Σ全部区域领料`，领料在 `BEGIN IMMEDIATE` 事务内即时校验，不足即回滚。
2. **客户确认关联具体版本**：清单按区域递增版本；只能确认最新版本，旧版本返回 `VERSION_STALE`。
   已确认版本在新版本（草稿→确认）产生前持续有效。
3. **替换授权**：替代提案必须客户确认；**主视觉区域未经确认一律拒绝替代花领料**（`HERO_NOT_AUTHORIZED`）。
   清单出新版本后，旧提案自动过期，须按新版本重新提案；确认时锁定 `decided_version`。
4. **多组重复领料不抹除**：在配额内允许，但跨小组自动写 `incident(kind=duplicate)` 并在界面预警。
5. 萎蔫/提前开花/运输折损按批次记录折损枝数；临时追加、撤场回收均有据可查。

## 测试

```bash
python3 -m unittest discover -s tests -v
```

覆盖：库存跨区占用、配额上限、**版本过期**、**替换授权**（主视觉锁定/驳回/授权枝数）、
质检折损、追加单据，以及 **12/20 线程并发领料不超卖**，外加 HTTP 端到端冒烟（含 409 冲突码）。

## 目录结构

```
app/db.py        SQLite schema、连接与串行化事务
app/service.py   业务规则（库存占用 / 版本 / 替换授权 / 领料 / 结算）
app/server.py    零依赖 HTTP：JSON API、静态文件、multipart 照片上传
app/seed.py      样例数据（区域平面图、缺货替代、临时追加、SVG 效果图/前后对比照）
web/             单页前端（index.html / css / js）
data/            运行期生成：floral.db 与 uploads/（已 gitignore）
tests/           unittest 测试
```
