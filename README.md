# 💐 婚礼花艺现场管理系统

花艺团队按婚礼区域管理花材清单：品种 / 颜色 / 枝数 / 到货日 / 冷藏位置 / 效果图；采购到货验收后，布置人员按区域领料并上传完工照片。零第三方依赖，仅用 Node.js ≥ 22 内置的 `node:sqlite` 与 `http`。

## 一条命令启动

```bash
npm start          # 重建数据库 + 写入缺货/临时追加样例 + 启动 http://localhost:3000
```

- 数据存于 `data/floral.db`（SQLite，数量与版本均落库）
- 照片存于 `data/photos/`（本地文件，效果图/对比图/完工照）
- 确认通知走**模拟适配器**：写入 `notifications` 表并追加 `data/notifications.log`

## 六个页面

| 页面 | 能力 |
|---|---|
| 花材配额 | 区域平面图（点击切换）对应花材清单、效果图、配额/已领进度；全场库存占用总览 |
| 到货质检 | 按批次验收，登记合格/不合格枝数与原因（到货萎蔫/提前开花/运输折损）、冷藏位置 |
| 区域领料 | 按区域+花材领料；全部尝试（成功/超配额/重复领料/未授权替换/库存不足）留痕 |
| 替换确认 | 替代单前后照片并排，标出枝数、每枝价差与合计价差、视觉差异；客户确认/拒绝 |
| 现场核对 | 临时追加、撤场回收、完工/核对/撤场照片上传、各区域配额实领对照 |
| 结算 | 按区域×花材列计划/替代/追加，替代价差、回收抵扣、应付合计 |

## 核心业务规则

- **配额不可双占**：同一枝数库存不能被两个区域重复占用；区域配额 = 当前版本计划 + 已批追加 + 已确认替代转入 − 替代转出，同时受全场合格库存（到货验收合格 − 已领）约束。
- **版本关联**：每张替代单绑定具体清单版本；版本修订后旧单确认即判「版本过期」，需按新版本重提。
- **主视觉授权**：主视觉区域（花门，珊瑚色 ★ 标记）替代单未经客户确认，布置端领取替代花材一律拒绝并记「未授权替换」。
- **并发安全**：领料在 `BEGIN IMMEDIATE` 事务内完成配额与库存校验，配合 `busy_timeout`，多组/多连接并发不会超卖。
- 重复领料、超配额、库存不足、未授权替换都会写入 `pickup_attempts` 留痕。
